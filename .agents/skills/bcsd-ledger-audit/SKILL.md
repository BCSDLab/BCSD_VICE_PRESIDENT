# BCSD 장부 검수

## 권한과 진입점

- 이 스킬은 검수 전용이며 운영 원본을 수정하지 않는다. 검수 요청은 Sheets 반영, 파일 덮어쓰기, 원격 문서 편집, Slack/DM 발송 권한이 아니다.
- 먼저 프로젝트 `README.md`, 해당 작업의 원본·산출물·템플릿, 현재 parser/generator와 인증 경로를 확인한다. README나 과거 지침과 구현이 다르면 실제 구현을 기준으로 검수하고 차이를 보고한다. 비밀값·개인 계정 정보를 출력하거나 기록하지 않는다.
- 거래 관리·납부 문서의 값 또는 설명을 고치는 일은 [관리 문서 업데이트](../bcsd-fee-management/SKILL.md), 제출 장부·증빙 산출물을 생성/수정하는 일은 [장부 작성](../bcsd-ledger-writing/SKILL.md)에 연결한다. 검수 결과만 전달하며 직접 수정하지 않는다.
- 면제·탈퇴·보안 트랙 제외와 회비 사유 판정은 [사유 자동 판단](../bcsd-fee-management/references/workflow.md#사유-자동-판단)의 단일 기준을 따른다. 별도 예외 규칙을 만들지 않는다.
- 세부 증거 수집과 신뢰성 함정은 [검수 절차](references/workflow.md)를 따른다.
- 의존성·인증·원본 접근이 준비되지 않았으면 [초기 설정](../bcsd-initial-setup/SKILL.md)을 참고한다. 검수 요청만으로 실제 설치·설정 변경이나 재인증을 실행하지 않는다.

## 전수 검수 범위

요청된 기간·파일·회원 범위를 먼저 확정하고, 가능한 범위에서 다음을 전수 대조한다.

1. 은행 원본 ↔ 거래 관리 문서 ↔ 납부 문서 ↔ 제출 장부의 입금·출금 건수, 중복 수, 날짜, 금액, 이름/거래 내용, 잔액과 회비 납부 표시.
2. 모든 출금과 제공된 모든 영수증·이체확인증: 원본 이미지의 날짜·merchant/수취인·총액·개별 금액·실수수료, 환불/취소, 누락, 오매칭, 중복첨부와 중복계상을 구분.
3. 제출 양식: 최초 템플릿과 실제 이전 제출 완성본을 비교하고, 입력값과 실제 서식 변화를 구별.
4. XLSX 데이터·수식·구조 및 HWPX 내부 구조와 실제 렌더링 페이지. 텍스트/파서 출력만으로 시각적 증빙이나 배치를 확인했다고 하지 않는다.

일부 원본에 접근할 수 없거나 실제 렌더링이 불가능하면 해당 항목을 검증 불가로 분리하고, 확보된 근거만으로 결론을 낸다. 생성 파일 수정은 장부 작성 스킬로, 운영 문서 변경은 관리 스킬로 넘긴다.
