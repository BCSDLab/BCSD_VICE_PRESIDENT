# 회비 관리 운영 절차

이 절차는 거래 기입·납부 반영·미납 집계를 위한 현행 자료 확인 및 기존 코드 사용 지침이다. 연도, 회칙, 시트 구조, 회원 상태는 바뀔 수 있으므로 매 작업에서 실제 원본을 다시 확인한다. 예시의 연도나 판정은 운영 기본값이 아니다.

## 1. 대상과 권한 확인

- 기준일(미납을 계산할 마지막 월), 대상 연도/월, 문서, 회원/트랙, 요청된 변경을 특정한다. “검수” 또는 “대조”는 읽기 전용으로 해석한다.
- 거래 원본 기입, E/G 보완, 납부 `O` 반영, 회비 사유 수정, 미납 안내 생성은 서로 다른 작업이다. 요청받지 않은 작업을 덧붙이지 않는다.
- 금융 문서의 쓰기는 승인된 대상과 셀만 허용한다. 쓰기 전 현재 값을 재조회하고, 결과도 다시 읽어 검증한다. DM이나 Slack 메시지는 별도 요청이 있어도 발송 범위·대상을 명확히 확인하는 별도 작업이며, 미납 계산만으로 발송하지 않는다.
- `fee_checker/keywords.json`은 공유된 전역 설정이다. 작업 과정에서 추가 키워드를 전역 파일에 저장하거나 대화형 질문에 답해 파일을 바꾸지 않는다. 키워드 변경 권한은 별도다.
- 개인 식별 자료는 판정에 필요한 최소 범위만 조회한다. 새 스킬·예시에 실제 개인 이름·학번·의료 상세·계정·비밀값을 복사하지 않는다. 사용자가 요청한 미납 명단과 실제 업무 보고에는 필요한 회원 이름·트랙·금액을 사용할 수 있으나 학번·연락처·의료 상세는 노출하지 않는다.

## 2. 실제 자료·구현 확인

1. 요청된 기간을 포함하는 **은행 원본**을 직접 찾는다. Drive에서 가장 최신인 파일이 요청 월과 다를 수 있으므로 연월·거래 기간을 확인한다.
2. `MANAGEMENT_SHEET_URL` 거래 관리 문서의 해당 `YYYY년` 시트와 `FEE_SHEET_URL` 납부 문서의 해당 `YYYY` 시트를 각각 조회한다. C 트랙, D 이름, E 비고, F~Q 월별 상태라는 배치를 현재 헤더와 대조하고, 행 번호를 과거 작업에서 가져오지 않는다.
3. 요청에 해당하는 원본/현행 회원 명부와 회칙(면제 조항, 개정 및 적용 시점)을 확인한다. 면제 신청서·승인 기록은 비고보다 우선하는 근거로 실제 조회한다. 다른 연도 시트와 과거 기록은 시점 및 동일인 확인을 위한 보조 근거다.
4. `README.md`, `fill_ledger.py`, `ledger_filler/filler.py`, `fee_check.py`, `fee_checker/checker.py`, `fee_checker/keywords.json`의 현재 내용을 필요한 범위에서 읽는다. README·이 문서와 구현이 다르면 현재 구현을 따르고 정확한 차이를 보고한다.

현재 확인한 README는 회비 규칙을 2026년 2월까지 월 10,000원, 2026년 3월부터 학기당 60,000원으로 기재한다. `checker.py`는 `SHEETS_TO_PROCESS = ["2025", "2026"]`으로 고정되어 있고, 2026년 1~2월을 월별로, 3~8월 및 9~12월을 학기 구간으로 계산한다. 실제 2학기는 9월~이듬해 2월이지만 계산기가 다음 연도까지 처리한다고 가정하지 않는다. 다음 연도 시트와 이월 표기를 따로 확인한다. 회칙/시트/코드가 이 설명과 달라졌으면 최신 실제 자료가 우선이고 차이를 명시한다.

## 3. 은행 거래 기입과 E/G 보완

- 표준 진입점은 `fill_ledger.py` → `ledger_filler/filler.py`다. 특정 파일을 지정하지 않은 실행은 Drive 최신 거래 파일을 선택하므로 요청 기간과 다르면 원본 파일을 명시해 사용한다.
- 자동 기입을 요청받았어도 이미 있는 월을 덮어쓰지 않는다. `--force`나 행 삭제는 사용자가 덮어쓰기를 명시적으로 승인했을 때만 고려한다. 업데이트 직전 셀을 다시 확인하고 다른 사용자가 입력한 값은 보존한다.
- 원본과 결과를 `(거래일시, 부호 있는 금액, 거래 내용/이름, 잔액)`별로 중복 개수까지 대조한다. 합계만 맞는 것은 완전 대조가 아니다. 해당 월 건수, 소계, 연간 수식 결과도 확인한다.
- E열 내용 및 G열 비고는 영수증, 납부 문서, 이전 기록 등 확인 가능한 자료로 뒷받침되는 값만 입력한다. 같은 금액, 날짜, 송금인 이름만으로 거래 목적이나 회비 기간을 단정하지 않는다. 확인 불가 값은 추정 입력하지 말고 미확인으로 보고한다.
- 보완은 요청된 빈 셀만 대상으로 한다. 기존 문구·수동 입력을 지우거나, 거래 원본을 바꾸거나, 불필요한 캡션·산식을 문서에 덧붙이지 않는다.

## 4. 동일인·대상 여부 판별

- 동일인 판단은 이름 일치만으로 하지 않는다. 현재 명부의 회원 상태와 트랙, 필요한 경우 학번 등 안정적인 식별 근거를 확인하고 과거 납부 문서/거래 기록과 대조한다. 학번은 확인에만 사용하고 보고서에 싣지 않는다.
- 동명이인, 이름 표기 변화, 트랙 이동, 재가입 기록은 각각 별도 행/시기일 수 있다. 현재 트랙으로 과거 트랙의 기록을 임의 병합하지 말고 연결 근거를 찾는다. 이름·트랙·학번의 연결이 모호하면 대상 확정 또는 합산을 보류한다.
- 탈퇴 제외가 명시적으로 요청되면 과거 비고의 `탈퇴` 문자열만으로 제외하지 않는다. 현재 회원 명부와 트랙 및 학번 등으로 해당 개인의 **현역 여부**를 확인하고, 재가입·트랙 이동·동명이인과 구분한다. 확인된 탈퇴자는 요청된 미납 대상 집계에서 뺄 수 있지만 과거 거래·납부·미납 내역은 보존하고 임의 삭제/면제 처리하지 않는다.
- Security 트랙은 미납자 명단·미납 금액·안내 대상에서 기본 제외한다. 이 설정은 거래 관리 문서의 거래 전체 대조/입금 확인에서는 제외하지 않는다. 계산 시 `_normalize_track("Security")`를 기본 제외 집합에 포함하고, 사용자가 지정한 제외 트랙/회원도 합집합으로 더한다. 어떤 제외도 원본/납부 문서의 기록을 지우거나 상태를 수정하는 의미가 아니다.
- `졸업`, `탈퇴`, `활동 중지`처럼 현재 대상 여부를 가르는 상태와 특정 월 회비의 면제는 별개 판단이다. 졸업·탈퇴 시점이 이전에 발생한 미납을 자동 소거하지 않는다. 명시된 요청이 없는 한 기존 미납 기간을 보존하고, 청구 대상에서 제외할지와 면제 처리할지를 분리해 보고한다.

## 사유 자동 판단

키워드 자동 분류는 조사 시작점일 뿐 결론이 아니다. `keywords.json`의 단어를 비고에 찾았다는 이유만으로 해당 회원·연도·기간의 면제, 영구 제외 또는 미납 취소를 확정하지 않는다. 근거 수집 → 동일인 판별 → 적용 회칙/사유/유효 기간 해석 → 월 단위 제외 → 기존 함수 재계산 → 결과 검증/보고 순서로 판단한다.

### 근거 수집 및 판정

1. 납부 문서의 해당 회원 행·비고·월별 `O`/`-` 표기와 그 앞뒤 연도 기록을 확인한다. 관련 면제 신청서 및 승인 내역, 현행 회원 명부, 적용 회칙의 해당 조항과 적용 시점도 찾는다. 문구 한 줄로 결론을 내리지 않는다.
2. 이름뿐 아니라 현역 명부의 트랙·학번 등으로 동일인을 판별한다. 신청서와 비고의 대상이 다른 회원일 가능성, 재가입·트랙 변경, 동명이인을 확인한다.
3. **회칙이 면제 사유인지 결정한다.** 최신 적용 회칙의 면제 사유·조건·승인 요건을 읽는다. 현재 확인된 회칙 제27조는 군/질병 휴학, 임원, 멘토, 졸업 및 승인 사유의 면제를 규정하지만, 회칙 개정과 적용 시점이 달라질 수 있으므로 매 작업에서 최신 원문과 적용 시점을 검증한다. 이 범위 외 사유는 승인 기록과 조항 근거 없이 자동 면제하지 않는다.
4. 학적상 **일반 휴학은 자동 면제가 아니다.** 실제 승인된 면제 사유와 그 유효 기간이 확인될 때만 해당 월에 적용한다. 질병 휴학 등 사유가 허용될 수 있는 경우에도 실제 신청/승인·기간을 확인하며 의료 상세는 복사하거나 보고하지 않는다.
5. 시작·종료 연월을 달력 월로 정규화한다. 사유 발생일과 실제 면제 승인 유효일을 혼동하지 않는다. 시작/종료 월 경계, 괄호/연도 생략, 뒤 연도에 앞 연도 사유를 기재한 경우는 원문 신청서와 시트 표기를 찾아 연도를 확정한다. 문구만으로 기간을 연장하거나 소급하지 않는다.
6. 같은 월에 복수 사유가 있으면 각 사유의 승인 및 기간을 확인한 뒤 월 집합의 합집합으로 제외한다. 겹치는 기간은 이중 차감하지 않고, 서로 다른 사유가 끝난 뒤의 공백월은 면제하지 않는다. 회칙상 학기 도중 면제와 적용 금액 계산 규칙도 함께 검토한다.
7. 근거가 충돌하거나 불충분하면 다른 연도 시트, 실제 신청/승인서, 원본/현행 명부를 찾아 해결한다. 실제 자료에 도달할 수 없으면 `확인 필요`로 별도 분류하고, 추정한 금액을 확정 청구액에 넣지 않는다. 필요하면 가능한 금액 범위를 내부 확인용으로 분리하되, 확정 미납과 합산하지 않는다.

### 월 단위 제외와 프로그램 보정

- 납부 상태 `O`는 납부, `-`/`−`는 면제 표시, 빈칸은 미납 가능성을 뜻한다. 비고의 유효 면제 월은 표시와 별도로 검토한다. 실제 승인된 제외 월은 연도별 월 집합으로 기록하고, 기납 월·이미 면제 표시된 월과 중복 차감하지 않는다.
- 기존 키워드·파서가 놓친 사유를 자동 집계값에 그대로 둘 경우 과청구가 되는지 실제 근거와 월별 계산으로 확인한다. 예: 확인된 질병 휴학 면제 기간이 2026년 9월~2027년 2월인데 파서가 질병 휴식 표현을 인식하지 못하는 경우, 원본 시트·전역 `keywords.json`은 변경하지 않는다.
- 보정이 필요하면 원본을 보존한 **작업용 납부 파일 복제본**에만 근거가 확인된 사유/기간 표시를 임시 반영해 기존 `parse_sheet`, `parse_exclusion_periods`, `calculate_unpaid_detail`, `aggregate_unpaid_fees`로 재계산한다. 또는 해당 회원·연도의 추가 제외월을 명시적으로 보유하고, 기존 `calculate_unpaid_detail(..., inherited_excluded_months=...)`에 전달하는 작업용 입력으로 재계산한다. 원본에 쓰지 않고 전역 `EXCLUDE_KEYWORDS`/JSON을 바꾸지 않는다. 복제본/추가 제외 입력은 계산 후 폐기·보관 범위를 사용자 정책에 따른다.
- `aggregate_unpaid_fees`에는 사용자 지정 개별 월 제외 인자가 없고, `inherited_excluded_months`는 `calculate_unpaid_detail`에 제공된다. 집계 함수의 입력을 우회하면서 결과를 합산할 때에는 해당 연도·행 전체의 기납부/사유/트랙·회원 제외, 2025→2026 이월, 월별 미납과 학기별 미납을 기존 함수와 동일하게 적용했는지 건별 검증한다. 모든 후보에 추가 월이 같은 것은 아니다. 복제본의 비고를 이용하더라도 파서가 해석한 실제 제외 월과 대상 행을 확인한다.
- 보정 전후에 대상자의 미납 월/학기와 금액 차이를 비교하고, 사유·승인 기간 및 제외된 월 수를 근거로 기록한다. “계산기가 개선됨”이나 “자동 인식 수정됨”이라고 표현하지 않는다. 이는 해당 작업에 한정한 자료/추가 입력 보정이다.

### 기간·이력별 유의점

- **임원/멘토 기간:** 직책명만으로 한 해 전체를 면제하지 않는다. 실제 재임/활동 시작일·종료일, 해당 회칙의 면제 범위와 월 단위 규칙을 확인한다. 기간 일부만 겹치는 학기는 적용된 월과 산정 방식을 표시한다.
- **학기 중 면제:** `checker.py`는 학기 기간 중 일부 제외 월이 있고 활동 월 미납이 있으면 활동 월마다 월 10,000원으로 계산한다. 일반 학기 미납은 학기 60,000원이다. 실제 규정·적용 시점이 다르면 최신 규정 확인 결과를 우선하고, 기존 코드가 그 규칙을 표현하지 못하면 차이를 분리해 보고한다.
- **연말 이월:** 2학기는 9월~다음 해 2월이다. 2026 시트의 9~12월과 다음 연도 시트의 1~2월을 별도 확인하며 같은 행 번호를 가정하지 않는다. 현재 집계 함수는 2025/2026 시트만 처리하므로 그 뒤 연도까지 자동 합산했다고 말하지 않는다.
- **전년도 사유 기재:** 2026 면제 기간이 2025 행 비고에 기록된 경우 `aggregate_unpaid_fees`의 2025 시트 처리에서 2026 제외월을 이어받는 경로가 있다. 해당 기록이 같은 개인에게 속하는지, 영구 제외 키워드/기간 파싱 결과가 실제 의도와 일치하는지 확인한다. 반대로 다음 연도 비고의 앞 연도 기간도 해당 원본 행을 찾아 적용한다.
- **졸업 전 미납:** 졸업 이후 월의 대상자 제외와 졸업 전 확정된 미납은 다르다. 이전 미납은 졸업/탈퇴 문자열만으로 취소하지 않는다.
- **기납·환불·오입금:** `O` 표시는 실제 입금 및 적용 기간과 대조한다. 환불, 반송, 금액 부족/과다, 오입금은 실제 거래 내역과 납부 귀속을 확인한다. 거래 기록만 있고 어느 월 납부인지 불명확하면 귀속을 추정하지 않는다. `O`가 표시돼도 환불된 납부를 임의로 정상 납부로 두지 말고 승인된 수정 범위와 근거가 필요하다.
- **기간 없는 사유:** 기간 없는 키워드는 파서가 시트 전체를 제외할 수 있으나, 그 결과를 규정으로 간주하지 않는다. 실제 근거에 기간이 있는지 찾아 기간을 확인한다. 기간 없는 승인 사유가 명확해도 어느 시점부터 적용되는지 불분명하면 해당 월을 확정 제외하지 않고 확인 필요로 둔다.
- **재확인 요청:** 재확인 시 이전 요약·다운로드 파일·전회 계산값을 최신 근거 대신 사용하지 않는다. 가능한 최신 원본, 회원 상태, 회칙 및 납부 문서를 다시 조회하고 변경 시점을 비교해 재계산한다.

## 6. 기존 코드 사용과 부작용

- `fee_check.py`는 단순 읽기 전용 계산 명령이 아니다. 현재 `main()`은 회비 문서 다운로드 후 미납 계산, 안내문 파일 생성을 수행한다.
- `generate_message_files`는 출력 폴더의 기존 `*.txt`를 삭제하고 다시 만든다. 재확인 계산 목적으로 무심코 실행하지 말고 기존 출력 파일을 보존한다.
- 미인식 비고 대화에서 입력에 따라 실행 중 키워드가 추가되고, 코드 경로에 따라 전역 `keywords.json` 변경을 유발할 수 있다. 승인 없이는 대화형 키워드 수정 경로를 쓰지 않는다.
- `--send-dm`은 실제 Slack DM을 발송한다. 사용자의 명시적 별도 승인이 없으면 절대 사용하지 않는다.
- 안전한 계산은 최신 납부 문서를 읽기 전용으로 다운로드하고 작업용 복제에서 기존 계산 함수를 호출하는 절차로 수행한다. 계산용 임시 자료와 보고용 출력이 기존 운영 파일을 덮어쓰지 않도록 격리한다. 표준 함수가 현재 시트 연도 밖을 처리하지 못하면 연도 범위를 임의 추정하지 않는다.
- 확인된 기존 코드 제약: 면제 키워드 목록의 부분 문자열 매칭과 `parse_exclusion_periods` 파싱 결과는 근거가 아니다. 기간 없는 매칭은 해당 시트의 모든 월로 해석될 수 있고, 날짜 파서는 연도/기간 형식에 따라 범위를 잘못 읽을 수 있다. 실제 비고 및 확인 자료와 대조한다. `aggregate_unpaid_fees`는 2025년 행 중 영구 제외 키워드가 있는 경우에만 2026 제외월을 이월한다. 결과를 반드시 개별 회원·월과 대조한다.

## 7. 미납 계산·월 귀속 및 제외 합계

1. 요청 기준일의 마지막 월을 특정한다. `calculate_unpaid_detail`의 2026 로직은 `current_month - 1`까지 확인하므로 10월 말 기준은 `current_month=11`이다. 아직 시작하지 않은 학기는 청구하지 않되, 이미 시작된 정상 활동 학기는 완료 전이라도 적용 규칙에 따라 학기비 전액을 계산한다. 부분 면제·활동월 계산은 확인된 규정과 기존 함수의 실제 동작을 대조한다.
2. 월별 `O`, 면제 `-`/`−`, 빈칸, 승인된 추가 제외 월을 각각 분류한다. 실제 `O`를 숫자 `0`으로 바꾸지 않는다.
3. `2025` 시트는 구현상 월 10,000원 계산, `2026` 시트의 1~2월은 월 10,000원, 3~8월 및 9~12월은 구현상 학기별 계산이다. 2026 학기 중간 제외가 있으면 코드상 남은 활동 월별 금액 산정이 적용될 수 있다. 근거 규정 및 실제 월 표시와 대조한다.
4. 2025→2026 제외월 상속이 포함될 수 있으므로 이전 시트 미납과 현행 미납을 따로만 더하지 말고 `aggregate_unpaid_fees` 경로도 확인한다. 단, 현행 함수 시트 범위가 제한적임을 보고한다.
5. Security 트랙과 사용자 지정 개인/트랙 제외는 **대상 명단에서만** 제외한다. 은행 원본/관리 문서 거래 대조, 납부 문서 보존에서는 제외하지 않는다. 회비 사유 면제와 집계 대상 제외도 별개로 구분한다.
6. 확인할 수 없는 사람은 확정 미납 합계에 넣지 않는다. 표기된 추정 금액이 있다면 `확인 필요` 참고값으로 따로 분리하고, 확정액과 섞거나 청구하지 않는다.
7. 합계를 회원별 금액과 재합산하고, 월 단위 제외가 기납부·면제와 중복 차감되지 않았는지 확인한다. 전후 비교로 보정 차이를 설명한다.

## 8. 승인된 문서 수정과 검증

- 납부 문서 반영은 요청된 입금의 기간 귀속을 확인한 후 해당 월 칸만 대문자 `O`로 입력한다. 0, 면제 기호, 메모, 수식, 기존 셀 서식은 보존한다. 입금 확인만 요청했으면 `O`를 쓰지 않고 관리 문서와 납부 문서 상태 차이를 보고한다.
- 관리 문서 기입은 대상 거래만 반영하고 월별 행 건수·소계·연간 합계 수식을 확인한다. E/G 수정은 근거가 있는 빈칸에만 적용한다.
- 모든 쓰기 전 셀 값을 재조회한다. 값이 예상과 다르거나 다른 사용자의 수정이 보이면 중단하고 최신 상태로 다시 판단한다. 쓰기 후 실제 변경 셀을 읽고 허용된 범위 밖 변경이 없는지 확인한다.
- `O` 반영/거래 기입 이후 계산 요청 범위에서만 기존 함수를 다시 호출해 검증한다. 전체 연도·전체 회원이 확인되지 않았다면 전체 정상이라고 표현하지 않는다.
- 수식이 있는 문서는 수식과 계산 결과를 모두 가능한 범위에서 확인한다. 문서 권한·자료 접근이 제한되면 접근한 자료와 제한된 범위를 명시한다.

## 9. 보고 형식

보고는 개인 정보 노출을 최소화하면서 계산 범위를 분명히 한다. 승인된 관리용 명단이 필요한 경우에만 요청된 대상의 식별 정보를 사용한다.

- **기준일/기준월:** 어느 문서의 어느 월까지 확인했는지 명시한다.
- **트랙별 확정 미납:** `이름: 미납 기간 / 금액`으로 기록한다. 월·학기 기간을 분명하게 표시하고 트랙별로 묶는다.
- **이월:** 이전 연도 미납과 다음 연도 월/시트 이월 여부를 확정 미납과 별도로 설명한다.
- **제외:** Security 및 요청된 트랙/개인 제외, 승인된 면제 월은 근거 유형과 적용 월 수/범위를 분리해 기록한다. 운영 문서의 거래 내역은 보존되었음을 오해 없게 표현한다.
- **확인 필요:** 사람/기간/사유가 불명확하거나 자료에 도달하지 못한 사례 수와 확정되지 않은 금액을 별도 기재한다. 추정 청구를 하지 않는다.
- **합계:** 확정 미납 합계만 제시하고, 제외 대상 합계/확인 필요 금액은 별도 라인으로 둔다. 총액을 한 숫자로 뭉치지 않는다.
- 실제로 수행하지 않은 문서 수정, 전체 범위 검증, DM 발송 또는 프로그램 개선을 주장하지 않는다. 재확인 요청이면 최신 자료를 다시 조회했는지와 전회 대비 변경점을 밝힌다.
