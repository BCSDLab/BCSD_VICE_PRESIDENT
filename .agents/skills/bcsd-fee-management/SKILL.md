# BCSD 회비 관리

## 역할과 경계

- 은행 거래 원본을 기존 관리 문서에 반영하고, 근거 있는 거래 내용(E)·비고(G)을 보완한다. 회비 납부 문서에서 기납부·면제·미납을 대조하고, 요청받은 납부 `O` 표시 또는 기준일까지의 미납 계산을 수행한다.
- 사용자가 요청한 대상 연월·회원·문서·변경 범위만 처리한다. 거래 기입 권한이 납부 `O` 반영 권한이나 원격 문서 전반 수정 권한을 뜻하지 않는다. 검수만 요청받으면 읽기 전용이다.
- 요청에서 도출한 금융 문서의 변경 대상·기간·셀 범위만 수정한다. 사용자가 셀 주소를 직접 지정하지 않아도 실제 문서에서 대상 행을 찾아 범위를 특정한다. Slack DM 발송 및 전역 `fee_checker/keywords.json` 수정은 별도 권한이다.
- 미납 안내문·DM 발송 자체는 이 스킬의 작업이 아니다. 필요하면 사용자가 별도 요청하도록 안내한다. 제출용 장부·증빙 제작은 [장부 작성 스킬](../bcsd-ledger-writing/SKILL.md), 변경 없는 독립 검토는 [장부 검수 스킬](../bcsd-ledger-audit/SKILL.md)을 따른다.
- 기존 표준 스크립트와 계산 함수를 재사용한다. 자체 계산 규칙·별도 생성기를 만들어 대체하지 않는다. 현재 코드에 기능이 없으면 한계를 설명하고 작업용 복제나 명시적 제외 입력으로 한정하여 기존 함수를 보정한다. 프로그램이 개선됐다고 주장하지 않는다.

## 진입점과 현재 확인 대상

매 작업 시작 전 실제 대상 자료와 최신 구현을 읽는다. 과거 스킬 설명이나 README와 구현이 다르면 현재 코드를 기준으로 처리하고 차이를 보고한다.

| 목적 | 진입점/자료 |
|---|---|
| 은행 거래 원본→관리 문서 | `fill_ledger.py`, `ledger_filler/filler.py` |
| 회비 납부 문서·미납 계산 | `fee_check.py`, `fee_checker/checker.py`, `fee_checker/keywords.json` |
| 관리 문서의 회비·월별 거래 | `MANAGEMENT_SHEET_URL`의 `YYYY년` 시트 |
| 납부 상태·비고 | `FEE_SHEET_URL`의 `YYYY` 시트 |
| 사유·대상·시점 근거 | 현행 회원 명부, 해당 연도 원본 문서 및 셀 비고, 실제 면제 신청서, 적용 회칙 |

세부 조회·판단·계산·검증 절차는 [운영 절차](references/workflow.md)를 따른다. 현재 `fee_checker/checker.py`는 `2025`, `2026` 시트만 처리하고 면제 키워드·기간을 파싱한다. 집계는 기존 `aggregate_unpaid_fees` 및 `calculate_unpaid_detail` 경로를 사용한다. 현재 코드 한계 및 주의할 부작용은 운영 절차에서 확인한다.

## 기본 처리 순서

1. 요청의 기준일/기준월, 대상 연도, 대상 회원·트랙, 조회/수정 범위를 구체화한다. 현재 거래 원본·관리 문서·납부 문서와 최신 회원/회칙 자료를 조회한다.
2. 은행 거래를 관리 문서와 대조해 중복 건수까지 확인한다. 거래 내용·비고는 원본 증빙 또는 확인 가능한 기존 기록에 근거할 때만 보완한다.
3. 이름만으로 동일인을 합치지 않는다. 현재 회원 상태·트랙·확인 가능한 학번과 과거 기록의 동일인 근거를 교차 확인한다.
4. 적용 회칙의 버전·적용 시점, 면제 사유와 유효 기간을 확인하고 월 단위 제외를 판단한다. 단순 키워드 일치는 판정이 아니다. 불명확한 건은 먼저 신청서·다른 연도·원본/현행 명부를 찾아 확인한다.
5. 납부 문서의 `O`/면제 표기, 이월·기납부와 계산 기간을 적용해 기존 함수로 다시 계산한다. 기본 Security 제외는 사용자 지정 트랙·회원 제외와 합집합으로 적용하되, 거래 및 문서 기록은 보존한다.
6. 쓰기 권한이 요청된 경우 셀 값을 쓰기 직전 재조회하고 허용된 셀만 수정한다. 변경 뒤 문서 값·수식·보존 상태를 재조회한다.
7. 보고는 트랙별 `이름: 미납 기간 / 금액` 형식으로 하되, 기준일·이월·제외·확인 필요 건·합계를 분리한다. 판단 근거와 실제 계산 범위에 한정한다. 상세 규칙은 운영 절차를 따른다.
