# 장부 작성 작업 절차

이 절차는 기존 저장소 구현을 안전하게 호출하고 결과를 확인하기 위한 것이다. 기간·파일·제출 요구는 매 작업의 최신 원본으로 확인하며 아래 예시는 기본값이 아니다.

## 현재 구현과 제약 확인

작업 직전 `README.md`와 대상 코드를 다시 읽는다.

| 진입점/모듈 | 현재 동작 및 주의점 |
|---|---|
| `main.py` | 위치 인자는 시작·종료 기간, 선택 옵션은 `--transfer-proof PDF`뿐이다. 작업 디렉터리 기준 `templates/`, `output/`, `receipt_images/`를 쓴다. Linux/macOS는 HWPX 템플릿이 필요하다. |
| `ledger/membership_fee_parser.py` | 연도별 관리 문서를 파싱해 기간 필터링 후 날짜순 정렬한다. 장부의 시작 잔액은 첫 거래 후 잔액에서 첫 거래 부호 금액을 뺀 값, 종료 잔액은 마지막 거래 후 잔액이다. 동시간 거래의 은행 잔액 연결 순서는 보장하지 않는다. |
| `parse_source` | XLSX E열 hyperlink 또는 `HYPERLINK` 수식의 첫 링크만 수집한다. Sheets 셀의 `textFormatRuns`에 여러 링크가 있으면 빠질 수 있어 원본에서 전부 확인해야 한다. |
| `ledger/hwp/image_downloader.py::run` | `row_N_` 이미지 및 `row_N_fee`를 재사용한다. 기간·거래 식별자가 없어 다른 데이터셋에서 인덱스가 겹치면 잘못된 캐시가 연결될 수 있다. Docs 이미지와 Drive 자료는 기존 OAuth/API 경로를 쓴다. |
| `ledger/hwp/transfer_proof.py` | `pdftotext`/`pdftoppm`으로 PDF를 파싱·이미지화한다. 먼저 날짜+총액으로 매칭하고, 남은 레코드에는 금액만으로 재시도한다. 페이지 미매칭을 출력하지만 매칭 결과의 독립 확인은 작업자가 해야 한다. |
| `ledger/hwp/hwp_generator_xml.py` | 이미지가 없거나 열 수 없으면 해당 증빙 표를 건너뛴다. HWPX를 갱신하며 새 그림 바이너리·ID를 구성한다. |
| `hwp_generator_xml.py` 및 `hwp_generator.py` | `이체수수료` 플래그가 참이면 제목에 `(이체 수수료 500원)`을 고정 출력한다. 실제 PDF 수수료가 0보다 큰지만 플래그에 반영되므로 실제 금액이 500원이 아니면 불일치 가능성이 있다. |

위 제약을 해결한다며 사용자 요청 없이 코드·양식·캐시를 수정하지 않는다. README에서 현재 구현과 다른 설명을 발견하면 구현을 우선하고 차이를 결과에 명시한다.

## 접근과 작업 폴더

- `MANAGEMENT_SHEET_URL`은 관리 문서 다운로드에 필요한 설정이다. README의 현재 설명은 Google OAuth 클라이언트 JSON과 공유 `.google_token.json` 흐름이다. 과거 서비스 계정 환경변수 단정은 적용하지 않는다. 인증 키·토큰 값은 출력하지 않는다.
- `.env`를 작업 폴더에 복사하지 않아도 원래 CLI를 별도 위치에서 실행하도록 프로젝트 루트의 `.env`를 로드하고 상대 인증 경로를 절대 경로로 바꿀 수 있다.
- 안전한 실행은 별도 임시 작업 폴더에서 기존 `main.py`를 그대로 호출한다. 템플릿은 읽기 전용 링크, 출력과 `receipt_images`는 작업 전용으로 둔다. 새로운 생성기나 `--image-dir` 등 존재하지 않는 옵션을 만들지 않는다.

## 기존 main.py 격리 실행

프로젝트 루트에서 실행할 Python 예시다. 기간과 PDF 경로를 실제 요청으로 바꾸며 확인증을 넣지 않으면 `proof = None`으로 설정한다.

```python
import os
import subprocess
import tempfile
from pathlib import Path
from dotenv import load_dotenv

root = Path.cwd().resolve()
load_dotenv(root / '.env')
start, end = '2026-07', '2026-10'  # 실제 요청으로 교체
proof = root / 'report(1).pdf'     # 추가하지 않으면 None
work = Path(tempfile.mkdtemp(prefix='bcsd-ledger-writing-'))
(work / 'templates').symlink_to(root / 'templates', target_is_directory=True)
(work / 'receipt_images').mkdir()  # 다른 기간의 row_N 캐시와 분리

# README 기준 현재 인증은 OAuth. 기존 토큰이 존재하면 동일 토큰을 사용한다.
if (root / '.google_token.json').is_file():
    (work / '.google_token.json').symlink_to(root / '.google_token.json')

# 상대 경로로 설정한 OAuth 클라이언트 파일은 별도 cwd에서도 찾도록 절대화한다.
env = os.environ.copy()
key = 'GOOGLE_OAUTH_CLIENT_JSON'
if env.get(key) and not Path(env[key]).is_absolute():
    env[key] = str((root / env[key]).resolve())

args = [str(root / '.venv/bin/python'), str(root / 'main.py'), start, end]
if proof is not None:
    proof = proof.resolve()
    if not proof.is_file():
        raise FileNotFoundError(proof)
    args += ['--transfer-proof', str(proof)]
subprocess.run(args, cwd=work, env=env, check=True)
print('검증 대상:', work / 'output')
```

- 격리 폴더는 새 산출물·캐시의 인덱스 충돌을 방지한다. 재사용할 캐시는 기간뿐 아니라 `row_N`이 동일 거래인지도 대조한다.
- 코드의 `load_dotenv()`는 실행 환경에 설정되지 않은 변수의 경우 현재 디렉터리 `.env`를 읽는다. 위 예시는 루트 `.env`의 값을 부모 환경에 로드해 전달한다. 비밀값을 로그에 출력하지 않는다.
- 임시 실행에서 OAuth가 새 인증을 요구한다면 기존 인증 정책에 맞춰 진행한다. 토큰을 불필요하게 복제·삭제하지 않는다.
- 실행 결과는 작업 폴더 `output/`에 저장된다. 이 실행만으로 기존 완성본 표지 입력이나 캡처가 복원되지 않는다. 검증 전 교체 금지.

## 거래·잔액·증빙 검증

1. 관리 문서와 은행 원본에서 요청한 월·기간을 확인한다. 최신 Drive 파일이 자동 선택되는 다른 CLI와 달리 `main.py`는 관리 문서 URL에서 내려받아 요청 기간을 필터링한다. 요청 기간과 파일의 실제 범위를 혼동하지 않는다.
2. 원본 거래와 장부를 `(날짜·시각, 부호 있는 금액, 내용/이름, 잔액)` 기준으로 대조하며 중복 건수도 확인한다. 합계 일치만으로 충분하지 않다. 누락·중복·정렬 차이가 있으면 원본을 조사하고 값을 추정 수정하지 않는다.
3. 시작 잔액은 기간 첫 거래의 거래 후 잔액에서 첫 거래 금액을 부호 포함하여 뺀다. 종료 잔액은 기간 마지막 거래 후 잔액이며 기간 종료 시점까지 거래가 더 없는지 확인한다. 은행 화면 상단 현재 잔액은 이 값의 대체가 아니다.
4. 연속 거래 잔액은 `다음 잔액 = 이전 잔액 + 입출금액`으로 확인한다. 같은 시각 거래 순서 차이는 잔액 연결 증거로 해결하고 관리 문서를 몰래 재정렬하지 않는다.
5. 모든 지출 링크·이미지 자료를 확인한다. 파서가 반환한 첫 링크만으로 증빙 완전성을 판단하지 않는다. 합산 정산이면 모든 링크의 개별 금액과 실제 수수료를 대조한다.
6. 캡처가 필요하면 사용자가 준 원본을 사용한다. 실제 픽셀 해상도에서 날짜·거래·금액·잔액이 보이는지 확인한다. 채팅 미리보기 크기로 좌표를 추정하거나 캡처를 조작하지 않는다.
7. 템플릿의 통화 기호, 가로 페이지 분할, 인쇄 문제를 임의로 수정하지 않는다. 선택이 필요한 변경은 사용자에게 알리고 승인·원본 유지 선택을 확인한다. 숫자를 `원` 문자열로 바꾸어 표시 형식을 우회하지 않는다.

## 완성본에 확인증만 추가

### 페이지 매칭

1. 정확히 지정된 PDF 경로·파일명(예: `report(1).pdf`와 `report-1.pdf`는 서로 다른 파일)과 페이지 수를 확인한다.
2. 기존 `--transfer-proof` 경로를 사용한다. 모든 페이지의 날짜·입금액·수수료·수취인·시각을 장부 거래와 대조하고 미매칭·중복 사용을 점검한다.
3. `입금금액 + PDF의 실제 수수료 = abs(장부 출금액)`을 독립적으로 확인한다. 수수료가 0원인 확인증도 사용자 자료의 일부이므로, “수수료 있는 거래만”이라는 별도 지시가 없으면 제외하지 않는다.
4. 매처는 날짜+총액 우선 매칭 뒤 남은 페이지/거래를 금액만으로 다시 매칭한다. 날짜 불일치 폴백을 자동 승인하지 말고 수취인·거래 시각 등으로 같은 거래임을 확인한다. 같은 날짜와 금액의 복수 후보를 PDF 순서만으로 구분하지 않는다.
5. 실제 수수료와 생성기 표기 플래그를 따로 확인한다. 현재 생성기는 `True`에 고정 `500원`을 표시하며 PDF의 실제 수수료가 500원인지 보장하지 않는다. 실제 수수료가 다르면 원본 확인증을 근거로 요청된 산출물의 수수료 문구만 바로잡고 금액·양식·다른 지출이 보존됐는지 검증한다. 이 작업이 스크립트·양식 변경까지 허용하지는 않는다.

### 기존 HWPX 보존 및 반영

완성본이 있는 경우, 확인증을 붙인 새 전체 문서로 기존 파일을 덮어쓰지 않는다. 기존 표지, 잔액, 캡처, 수동 수정 문구, 장부 내용 및 이미지 바이너리를 보존하고 매칭된 확인증만 반영한다.

1. 기존 문서·장부 해시와 표지 XML, 스타일, 지출 순번, 이미지 참조를 별도 기록한다.
2. 격리 작업 폴더에서 기존 CLI를 실행해 확인증 이미지 및 매칭 기준 결과를 만든다. 독립 생성기나 기존 코드 수정은 금지한다.
3. 새 출력과 현재 문서의 거래 순번·날짜·금액을 대조하고 실제 매칭된 확인증만 결정한다. 기존 문서 전체를 새 출력으로 바꾸지 않는다.
4. 기존 HWPX에서 기존 이미지 바이너리를 원본 그대로 보존한다. 새 확인증 이미지 파일만 추가하며 기존 그림을 재인코딩한 유사 이미지로 교체하지 않는다.
5. 그림 바이너리 ID·파일명·manifest 항목과 참조를 충돌 없이 연결한다. 복사하는 그림·문단의 ID, `instid`, `zOrder` 충돌을 확인하고, 의미가 같다고 검증하지 않은 스타일 ID를 그대로 가져오지 않는다.
6. 확인증 이미지는 기존 셀 영역 안에 배치한다. 행간·셀 여백을 포함한 높이와 행별 이미지 너비가 셀을 넘지 않게 하며 셀·표 크기 자체는 키우지 않는다.
7. 비대상 지출, 기존 이미지, 표지·장부·삭제된 문구 상태가 변하지 않았는지 대조한다. 기존 이미지 전체와 확인증 전체가 의도한 거래에 실제 포함되어야 한다.
8. 문서에 원본에 없던 설명·산식·캡션을 추가하지 않는다. 확인증만 추가하고 자체 출력 검증 전까지 기존 완성본을 보존한다.

## 자체 출력 검증 체크리스트

| 대상 | 확인 내용 |
|---|---|
| 장부 거래 | 원본 거래 전건·중복 수, 날짜, 입출금, 잔액 흐름, 출력 순번, 숫자 타입, 요청 외 내용 및 스타일 |
| 잔액 | 기간 시작·종료 잔액 산식과 기간 끝까지 거래 유무. 계좌 현재 잔액과 혼동 여부 |
| 지출 증빙 | 모든 출금·모든 링크의 실제 이미지 존재, 캐시 인덱스 적합성, 원본 이미지 해시·해상도 |
| 확인증 | 지정 PDF의 페이지 전부, 매칭·미매칭·중복, 날짜·수취인·시각·실수수료, 표시된 수수료 액수 |
| XLSX 양식 | 템플릿 대비 스타일·행/열 치수·병합·인쇄 설정, 표지·잔액 입력 |
| HWPX 구조 | ZIP 무결성, manifest의 이미지 ID·파일, 참조와 ID 충돌, 바이너리 보존, 미리보기 텍스트·이미지 |
| 실제 출력 | 렌더링 가능한 환경에서 표지, 확인증, 다중 이미지, 마지막 거래, 잘림·누락 및 페이지 분할 |

- 실제 렌더링을 가능한 범위에서 수행한다. 텍스트 검사만으로 이미지 위치·잘림을 확인했다고 하지 않는다. LibreOffice 등 변환기를 쓴 경우 해당 환경과 경고·개체 누락 영향을 기록한다. 한컴 한글을 사용하지 않았다면 사용했다고 표현하지 않는다.
- HWPX의 `Preview/PrvText.txt`·`Preview/PrvImage.png`도 수정 후 문구·표지와 일치하는지 확인한다.
- 이미지 용량이 큰 경우 파일 크기를 보고한다. 임의 JPEG 변환·해상도 축소·양식 변경으로 용량을 줄이지 않는다.
- 수정본만 검증 후 게시한다. 사용자 원본·템플릿·인증 자료·기존 캐시를 삭제하지 않는다. 변경 사항과 검증 못한 부분을 분리해 보고한다. 완성본의 전반적인 독립 검수는 [장부 검수](../../bcsd-ledger-audit/SKILL.md)로 연결한다.
