# 장부 작성

## 역할과 경계

이 스킬은 사용자 요청에 따른 총동아리 제출 장부·증빙 생성 및 완성본에 확인증 추가만 담당한다. 주요 진입점은 `main.py`와 `ledger/membership_fee_parser.py`, `ledger/hwp/`의 기존 이미지·문서 생성 모듈이다. 운영 절차와 격리 실행 예시는 [작업 절차](references/workflow.md)를 따른다.

- 관리 Sheets의 셀 변경, 거래 기입, 회비 납부 `O` 반영, 미납 안내·DM 발송은 이 작업에 포함되지 않는다. 필요하면 [관리 문서 업데이트](../bcsd-fee-management/SKILL.md)로 분리한다.
- 생성물의 독립적인 회계·양식 검수는 기본 읽기 전용인 [장부 검수](../bcsd-ledger-audit/SKILL.md)에 맡긴다. 이 스킬은 생성한 결과물의 자체 출력 검증을 반드시 수행한다.
- 장부 생성 요청은 원격 문서·Slack을 수정할 권한이나 완성 파일을 무조건 덮어쓸 권한이 아니다. 기존 완성본을 보존한 별도 경로에서 검증한 뒤, 사용자가 요청한 파일 수정 범위에서만 검증된 수정본으로 교체한다.
- README와 실제 진입점·템플릿·모듈을 작업 시점에 확인한다. 불일치하면 최신 코드를 기준으로 하며 영향과 차이를 보고한다. 사용자 요청 없이 스크립트나 템플릿을 고치거나 새 생성기를 만들지 않는다.
- 가상환경·인증·템플릿 등 실행 준비가 안 되어 있으면 [초기 설정](../bcsd-initial-setup/SKILL.md)을 먼저 따른다. 초기 설정 완료가 운영 문서 수정 권한을 뜻하지 않는다.

## 핵심 원칙

1. 기존 표준 스크립트·템플릿을 재사용한다. 문서 구조와 생성 계산 규칙을 별도로 만들지 않는다.
2. 서식·표지·인쇄 설정·기존 수동 내용·이미지를 보존한다. 제목 문구, 글꼴, 색상, 열 너비, 행 높이, 병합, 표·셀 크기, 여백을 임의 변경하지 않는다.
3. 요청되지 않은 산식·캡션·설명을 문서에 추가하지 않는다. 원본 문구에서 사용자가 삭제한 것도 재생성으로 되살리지 않는다.
4. 거래·잔액·수수료·증빙 결론은 확인 가능한 원본과 범위에 한정한다. 매칭 폴백이나 수수료 추정은 검증 없이 승인하지 않는다.
5. 비밀값·인증 자료·회원 개인정보를 문서나 보고에 복사하지 않는다.

## 진입 조건

요청에서 대상 시작·종료 월, 제출물 종류(장부, 증빙, 확인증 추가), 정확한 원본 파일 및 허용된 변경 범위를 확인한다. 저장소에서 확인 가능한 자료는 먼저 조사한다. 제출 차수·학기·제목은 현재 양식·공지·기존 제출본에서 확인하며 기간만으로 추정하지 않는다. 은행 원본, 관리 문서, 영수증, 템플릿, 기존 완성본의 역할을 구분한다. 실제 운영 Sheets 다운로드는 현재 OAuth 경로를 따르며, 장부 생성 요청만으로 Sheets에 쓰지 않는다.

## 생성 및 추가 작업

- 루트 README와 `main.py`, 파서, 해당 플랫폼의 HWP 생성기, 이미지 수집기, 확인증 파서를 확인한다. 기간은 실제 요청값으로 CLI에 준다. Linux/macOS는 `.hwpx` 템플릿을 요구하며 Windows는 선택된 기존 템플릿 확장자를 사용한다.
- 일반 실행은 `.venv/bin/python main.py YYYY-MM YYYY-MM`이며 확인증 PDF는 `--transfer-proof /정확한/경로.pdf`로 전달한다. 추가 옵션을 상상해 사용하지 않는다.
- `main.py`는 현재 작업 디렉터리 기준 `templates/`, `output/`, `receipt_images/`를 사용한다. `row_N_` 이미지와 `row_N_fee` 캐시는 거래 고유 식별자를 포함하지 않으므로, 다른 기간·인덱스의 캐시를 재사용하지 않는다. 출력 경로와 캐시를 분리하려면 [격리 실행 절차](references/workflow.md#기존-mainpy-격리-실행)를 사용한다. 실행은 기존 CLI를 호출해야 한다.
- 장부에서 날짜순 정렬은 같은 시각 거래의 잔액 연결 순서를 보장하지 않는다. 거래를 날짜·부호 있는 금액·내용·잔액과 중복 개수까지 원본에 대조한다. 계좌 현재 잔액과 기간 거래 잔액을 혼동하지 않는다. 기간 시작 잔액은 첫 거래 후 잔액에서 첫 거래 금액(부호 포함)을 뺀 값이며, 기간 종료 잔액은 마지막 거래 후 잔액이다. 이후 기간 말일까지 거래가 없는지도 확인한다.
- 관리 문서 파서는 E열 링크의 첫 hyperlink 또는 `HYPERLINK` 수식만 읽는다. `textFormatRuns`의 여러 링크를 포함한 모든 출금 증빙은 원본 Sheets에서 별도로 확인한다. 첫 링크만 반영됐다고 증빙 완료로 보지 않는다.
- 캡처·영수증은 원본 파일과 해상도로 확인한다. 필요한 날짜·거래·잔액이 실제로 보여야 하며 원본 바이너리를 임의 재인코딩하거나 해상도를 축소하지 않는다. 기존 셀 안의 표시 크기 조정과 원본 픽셀 변경은 구분한다. 없는 자료를 은행 캡처로 만들어 대신하지 않는다.
- 원본 통화 표시나 페이지 가로 분할을 발견하면 알린다. 원본 보존 선택 또는 수정 승인이 없으면 그대로 둔다. 통화 표시를 임의로 바꾸거나 인쇄 분할을 임의 조정하지 않는다.
- PDF 확인증은 사용자가 지정한 정확한 파일과 전 페이지를 대상으로 한다. 날짜·금액·수취인·시각을 대조하고 `입금금액 + 실제 수수료 = 장부 출금액 절댓값`을 독립 확인한다. 매처는 날짜 불일치 시 금액만으로 재시도하므로 해당 폴백은 자동 승인하지 않는다. 같은 날짜·금액은 수취인·시각으로 구분한다. 실제 수수료 0원도 제공된 자료 일부이며 임의 제외하지 않는다.
- PDF 확인증을 넣으면 현재 구현은 해당 지출의 기존 이미지 앞에 페이지 이미지를 추가하고, 페이지의 실제 수수료가 양수인지 여부로 수수료 플래그를 보정한다. 단, 생성기 제목 표기는 플래그가 참일 때 `500원`으로 고정된다. 실제 수수료가 다르면 확인증을 근거로 요청된 산출물의 수수료 문구만 바로잡아 검증한다. 스크립트나 양식 변경은 별도 요청 없이 수행하지 않는다.
- 기존 완성본에 확인증만 더할 때 새 생성본 전체를 완성본 위에 덮어쓰지 않는다. 기존 표지·잔액·캡처·수정 문구와 기존 이미지 바이너리를 유지하고 매칭된 확인증만 반영한다. 구체적인 기존 HWPX 대조·반영은 [작업 절차](references/workflow.md#완성본에-확인증만-추가)를 따른다.

## 자체 생성 결과 검증 및 보고

생성은 검수와 다르다. 자체적으로 실제 산출물을 열어 범위에 따른 거래 집합·중복·금액·잔액 흐름, 지출별 링크와 이미지·확인증 매칭을 점검한다. 템플릿과 출력의 서식·치수·표지·인쇄 설정을 대조하고, 확인증 추가에서는 기존 이미지와 문서 구조가 보존됐는지 확인한다. HWPX의 ZIP·manifest·그림 바이너리 및 참조 일관성을 확인한다. 텍스트 검사만으로 끝내지 말고 가능한 렌더링 출력에서 표지, 확인증, 다중 이미지, 마지막 페이지의 잘림·누락을 확인한다. 렌더러를 사용했다면 환경을 밝히며 한컴 한글에서 열지 않았다면 그렇게 확인했다고 말하지 않는다. 미검증 영역은 명확히 보고하고 독립 검수는 [장부 검수](../bcsd-ledger-audit/SKILL.md)에 연결한다.

결과 보고는 산출물 링크, 처리·미반영 건수, 실제 검증 범위와 남은 제한을 간결히 제시한다. 미확인 거래·페이지·형식을 정상이라고 단정하지 않는다. 큰 산출물은 파일 크기를 함께 알린다.
