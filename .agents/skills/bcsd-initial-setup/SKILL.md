# BCSD 초기 설정

## 역할과 권한

- 이 스킬은 회계 업무를 실행하기 전 환경을 준비·확인한다. 사용자가 스킬 작성만 요청했다면 문서만 작성하며 실제 설치·인증·설정 변경은 실행하지 않는다.
- 실제 초기 설정 요청에서는 필요한 로컬 가상환경·패키지·설정과 OAuth 캐시를 준비할 수 있다. 기존 `.env`, 가상환경, 인증 파일, 템플릿, 명부를 덮어쓰거나 삭제하지 않는다. 재설정·기존 값 교체는 별도 요청 범위로 판단한다.
- Google 동의 화면은 계정 소유자가 내용을 확인하고 승인한다. Cloud 프로젝트 생성, IAM 권한 확대, 조직 정책 우회, Slack 메시지 발송은 초기 설정에 묵시적으로 포함되지 않는다.
- 인증 파일·토큰·환경변수의 비밀값·회원 연락처를 읽어 출력하거나 스킬·로그·커밋에 복사하지 않는다. 비밀값 대신 설정 키의 존재 여부, 파일 존재/권한, 오류 유형만 보고한다.
- 설정을 확인하려고 `fill_ledger.py`, `main.py`, `fee_check.py`를 실제 업무 인자로 실행하지 않는다. 거래 쓰기, 출력 덮어쓰기, 안내문 삭제·재생성, 키워드 변경, DM이 발생할 수 있다.

## 실제 구현 확인

작업 전 `README.md`, `.env.example`, `requirements.txt`, `.gitignore`, `ledger_filler/filler.py`의 인증 흐름과 실행하려는 진입점을 확인한다. 설명과 구현이 다르면 현재 구현을 기준으로 하되 차이를 보고한다. 구체적인 명령과 읽기 전용 접근 확인은 [초기 설정 절차](references/workflow.md)를 따른다.

- 프로젝트 Python 최소 표기는 3.10이다. 실제 선택한 패키지의 Python 지원 범위와 OS를 확인하고 기존 `.venv`가 있으면 먼저 사용 가능 여부를 확인한다.
- 현재 Google 접근은 `GOOGLE_OAUTH_CLIENT_JSON`의 데스크톱 OAuth와 `.google_token.json`을 공유한다. 서비스 계정·DB·SSH 설정을 새로 요구하거나 대체 인증 흐름을 만들지 않는다.
- `requirements.txt`의 `pyhwpx`는 Windows 한글 자동화 경로에 필요하다. Linux/macOS는 HWPX XML 경로를 쓰므로 해당 Windows 전용 패키지 때문에 설치가 막히지 않게 절차의 OS별 설치 방법을 사용한다. 원본 의존성 파일은 임의 수정하지 않는다.

## 설정 순서

1. **환경 확인:** 저장소 루트, OS, Python, 기존 `.venv`·설정·인증·템플릿의 존재만 확인한다. 현재 작업 폴더와 무관한 홈 디렉터리·계정 자료를 수집하지 않는다.
2. **의존성:** 필요한 경우에만 프로젝트 가상환경을 만들고 해당 Python의 `-m pip`로 설치한다. 시스템 Python에 전역 설치하지 않는다. PDF 확인증에는 poppler, 실제 출력 검수에는 적절한 렌더러가 별도로 필요하다.
3. **환경변수:** `.env`가 없을 때만 `.env.example`을 새 파일로 복사하고 실제 사용 목적의 필수 항목을 채운다. 기존 파일에서는 누락된 설정만 처리한다. 예시 프로젝트·문서 ID·발신자·토큰을 실제 값으로 간주하지 않는다.
4. **OAuth:** Drive·Sheets·Docs API와 동의/테스트 사용자 설정, 실제 로그인 계정의 대상 자료 접근 권한을 확인한다. 현재 인증은 Drive 전체 범위를 요청하므로 인증 전에 이를 알린다. 기존 유효 토큰은 재사용하고, 새 인증은 기존 `_get_credentials()` 흐름으로 수행한다.
5. **입력 자료:** 공식 템플릿·목표 연도 시트·거래 폴더를 확인한다. 템플릿과 명부는 Git에서 제외될 수 있으므로 새 체크아웃에 없다고 새 양식을 만들지 않는다. Slack 명부·발신 정보는 안내/DM 기능을 실제로 준비할 때만 요구한다.
6. **안전 점검:** 오프라인 import·각 CLI의 `--help`, 필요한 명령의 존재를 확인한다. 온라인 점검은 지정된 Sheets/Drive/Docs의 메타데이터 읽기만 수행한다. 인증 성공이 모든 API·문서 접근 또는 쓰기 성공을 보장하지는 않는다.
7. **준비 상태 보고:** 오프라인 실행, OAuth, API별 접근, 템플릿, PDF/렌더러, 선택적 안내/DM 준비 상태를 나누어 실제 확인 결과와 부족한 항목을 보고한다. 확인하지 않은 기능까지 준비 완료라고 하지 않는다.
